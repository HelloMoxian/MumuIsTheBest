# 切水果体感游戏

状态：**正式实现**

入口：`游戏 → 切水果`，路由 `/games/fruit-slice`

## 1. 产品目标与隐私边界

切水果是木木学习岛第一个摄像头体感游戏。孩子可以单人挑战，也可以由两位家庭成员分别站在画面左右两边对战。页面进入完整沉浸式游戏舞台，但继续使用正式的“星际探索舱”视觉，不切换成橙色街机或高压竞技主题。

- 摄像头通过浏览器 `getUserMedia` 获取，只请求视频，不请求音频。
- MediaPipe Pose Landmarker 与 Hand Landmarker 都在浏览器本机运行；摄像头帧不发送到 Fastify、第三方模型服务或战报接口，也不保存到文件或浏览器存储。
- 摄像头只能在 `localhost`、`127.0.0.1` 或 HTTPS 安全上下文使用。Windows 与 macOS 都使用相同的标准 Web API；推荐现代 Chrome、Edge 或 Safari。
- 拒绝权限、模型初始化失败或没有摄像头时，保留单人鼠标/触控练习模式；鼠标只有一个指针，因此不会模拟双人对战。错误不会清空设置或阻塞历史战报。
- 本玩法没有数字作答输入，不渲染全局数字键盘入口，避免遮挡右上角历史战报或挥动舞台；语言与朗读驾驶舱继续保留。

动作识别参考了 Finger Frame 的“镜像摄像头 + MediaPipe VIDEO 模式 + Canvas 实时效果 + 平滑处理”思路，但本玩法的身体分区、手部轨迹、滑动阈值、双人规则和游戏渲染均为项目内实现。参考页面：`https://sophiamyang.github.io/finger-frame-effect/`。

## 2. 赛前设置

每局开始前可以调整：

| 设置 | 允许值与语义 |
|---|---|
| 人数 | 单人 / 双人 |
| 角色 | 爸爸、妈妈、木木、姥姥、奶奶、小姨；双人不能选择同一角色 |
| 时长 | 30 / 60 / 90 / 120 秒 |
| 密度 | 舒缓、标准、热闹、果雨；基础节奏为 1350 / 1000 / 720 / 520ms，每波实际间隔随机取基础值的 55%—165% |
| 飞行速度 | 0.75×—1.50×；整体物理时间缩放为旧版的 50%，同档速度约为旧版一半 |
| 物体大小 | 128—256px，默认 160px |
| 挥动灵敏度 | 轻轻一挥 / 标准挥动 / 大力挥动 |
| 炸弹 | 可开关；开启后约 9% 波次单独出现炸弹，固定扣 30 分 |
| 龙虾 | 可开关；开启后约 7% 出物组为可三连切龙虾 |

设置在本局开始后锁定。计时可以暂停，也可以主动结束；暂停时间不计入有效游戏时长。

## 3. 人体、手部与滑动判定

浏览器随应用加载本地 `@mediapipe/tasks-vision` WASM、手部模型和轻量人体姿态模型。优先使用 GPU delegate，初始化失败后自动回退 CPU。单人最多追踪 1 个身体、2 只手；双人最多追踪 2 个身体、4 只手。人体姿态约每 120ms 更新一次，手部在新视频帧上更新。

- 摄像头和识别坐标都按镜像画面展示；Canvas 会按照 `object-fit: cover` 的实际裁剪把模型坐标映射到游戏场地。
- 手部位置取手腕与四个掌指关节的平均掌心点，比单独使用指尖更适合大幅挥臂。
- 手部按上一帧最近距离保持稳定轨迹 ID；短时丢失 260ms 后释放，不把重新进入的手与陈旧轨迹硬连接。
- 单人使用整个画面。双人以镜像画面的中线强制分为左、右两个归属区，防止越过中线后切到对方的物体。
- 新掌心点使用 `alpha = 0.46` 指数平滑。轨迹最多保留 18 点和 520ms，绘制时用相邻点中点作为终点连续调用 Canvas `quadraticCurveTo`，形成二次贝塞尔光轨。

有效滑动必须同时达到最小位移和速度：

| 灵敏度 | 最小归一化位移 | 最小速度（画面尺度/秒） |
|---|---:|---:|
| 轻轻一挥 | 0.022 | 0.38 |
| 标准挥动 | 0.034 | 0.58 |
| 大力挥动 | 0.048 | 0.82 |

碰撞使用有效线段到物体圆形命中区的最短距离，不只检测最后一个掌心点，因此快速挥动跨过物体也能命中。碰撞核半径固定为物体绘制尺寸的 `42%`；默认 160px 物体对应 67.2px 半径，并随赛前尺寸同步放大。

## 4. 出物、碎裂与双人镜像

普通食物为胡萝卜、黄瓜、茄子、鸡腿和鱼。物体从画面下方按抛物线飞入；新版将完整物理时间缩放到旧版的 50%，同时让每波初始高度、上抛速度、横向速度、旋转和尺寸在安全范围内变化。

- 普通波不再只出一个物体：舒缓为 1—2 个、标准为 2—4 个、热闹为 3—5 个、果雨为 4—6 个。双人局为避免半屏拥挤，每边每波最多 3 个。
- 多食物波使用浅弧线、斜线或向心扇形三类编队。物体按稳定横向顺序和小幅高度差同时出现，让一条连续轨迹可以命中多个目标。
- 每波间隔独立随机，波与波之间的上抛速度也独立随机，因此会交替出现短促连波、高抛慢波和较低的快速波，不形成机械节拍。
- 双人局每次只随机一次左侧食物编队，再把种类、尺寸、`x` 与横向速度镜像到右侧；因此左右会同时飞出相同物体并沿相同镜像轨迹运动。
- 普通食物切中后生成两块对应碎片、同色果渍和分离运动；果渍约 700ms 淡出。
- 龙虾需要命中 3 次，每次都计分；最后一次播放龙虾碎裂动画。
- 炸弹和龙虾只使用独立波次，不会混入多食物编队。炸弹命中后播放独立冲击环、固定扣 30 分并清空当前连击。
- `prefers-reduced-motion` 下保留命中、碎裂与状态文字，关闭额外旋转、持续阴影和长光轨。

`assets/cut_image` 的 PNG 已经是带透明通道的独立动画帧，因此不再使用绿幕切图工具二次裁切，避免破坏碎片和特效的帧对齐。正式构建通过 Vite 静态资源 glob 直接打包它们。

## 5. 得分、连击和超级模式

普通食物与龙虾每次命中的基础分：

```text
clamp(round(12 + 挥动速度 × 24), 12, 80)
```

因此挥动越快，单次得分越高。炸弹固定扣分：

```text
30
```

- 两次成功命中间隔不超过 1200ms 时连击继续，否则从 1 重新开始。
- 2500ms 滚动窗口内达到 6 次成功命中会触发一次 6 秒超级模式。
- 超级模式内本玩家的命中得分严格乘 3；左右玩家的连击、超级计时和得分完全独立。
- 炸弹不触发加成，并会清空当前连击；不会用闪烁、羞辱或“失败”文案反馈。

## 6. 能量币

能量币与知识币是两个独立的钱包。能量币图标使用圆形代币结构，中心为青色力量闪电、上升箭头和运动轨迹；正式文件为 `assets/game/energy-coin.v1.png`。

- 只有角色“木木”参加的已完成场次会计算能量币。
- 木木每达到 500 分获得 1 枚，向下取整；不足 500 分不发放，单局最多 20 枚。
- 浏览器只提交战报，Fastify 根据角色和分数计算奖励并原子写入；浏览器不能自行声明能量币数量。
- 每局使用 UUID `eventId` 幂等保存。相同事件重复提交只返回原战报，不会重复增加能量币。
- 能量币继续由切水果钱包统一保存；“岩石与矿物”可以每 30 枚购买 1 把地质锤。购买请求使用 UUID `eventId` 幂等扣款，相同事件重复提交不会再次扣币或重复发锤，浏览器不能自行修改余额。

## 7. 历史数据文档

默认文件：`../data/learning/games/fruit-slice-history.json`；自定义 `APP_DATA_DIR` 时路径相对该目录保持不变。

顶层字段：

| 字段 | 语义 |
|---|---|
| `schemaVersion` | 当前固定为 1 |
| `id` / `stableId` | 稳定历史文件身份，`stableId = game-fruit-slice-history` |
| `createdAt` / `updatedAt` | 文件创建和最近更新时间 |
| `energyCoinBalance` | 独立能量币余额 |
| `sessions` | 全部完成场次，按写入顺序保存 |
| `energyCoinTransactions` | 地质锤等能量币消费账本，按事件 ID 幂等保存 |

每局保存：事件 ID、开始/完成/创建/更新时间、单人或双人模式、有效时长、完整赛前设置、胜方站位或平局，以及每位玩家的角色、站位、得分、普通食物命中、龙虾命中、炸弹命中、最高连击、最快挥动、超级模式次数和本局能量币。

`GET /api/games/fruit-slice/history` 同时派生：

- 每个角色的总局数、最高分、总分和累计获得能量币；
- 每一对角色的交手局数、各自胜局与平局；
- 前端按完整 `sessions` 展示最近每局分数。

`GET /api/games/fruit-slice/energy-coins` 是首页与自然玩法使用的轻量余额接口；`POST /api/games/fruit-slice/energy-coins/spend` 只接受固定 30 币的地质锤购买；`POST /api/games/fruit-slice/history` 校验并幂等保存完成战报。收入和消费共用同一写入队列与余额文件。目录权限为 `0700`，文件权限为 `0600`；写入使用单队列、同目录临时文件和原子替换。摄像头画面、手部坐标和完整轨迹从不进入历史文件。

## 8. 资产与依赖

- `assets/cut_image/food`：五类完整物体与两半碎片动画。
- `assets/cut_image/blood`：命中后短时果渍。
- `assets/cut_image/other`：炸弹、龙虾与龙虾碎片。
- `assets/cut_image/bar`、`score`、`start` 未用于正式 HUD；其橙色街机语言与设计系统冲突，HTML/CSS HUD 也更利于无障碍和高 DPI。
- `assets/cut_image/effect/double` 未使用，因为素材语义是双倍，而正式规则固定为三倍。
- `@mediapipe/tasks-vision` 1.0.1 使用 Apache-2.0；模型 URL、SHA-256 和本地发布规则见 `assets/models/mediapipe/README.md`。

## 9. 验收要求

1. 滑动阈值同时检查位移和速度；碰撞覆盖跨帧线段。
2. 速度提高时得分严格提高，超级模式严格三倍，炸弹固定扣 30 分。
3. 普通水果可按弧线、斜线或扇形成组出现；炸弹不混入多水果波次。
4. 双人同组物体的种类、纵向速度、尺寸一致，横向位置和速度镜像。
5. 摄像头权限拒绝、非安全上下文、模型失败、空历史、损坏历史和写入失败都有可恢复文字状态。
6. 同一战报重复提交不会重复记录或发币；双人胜负与角色最高分派生正确。
7. 摄像头停止、离页或结算后必须立即关闭所有视频轨道和 MediaPipe 任务。
7. 运行前端/服务端类型检查、单元测试和生产构建；鼠标模式用于无摄像头回归测试，不能取代真实摄像头人工验收。
