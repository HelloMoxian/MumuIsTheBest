# 全局数字键盘

状态：**已实现**

## 1. 入口与用途

- 首页顶部“数字键盘”与“学习大厅”“功能测试”并列。
- 其他正式页面在顶部安全区显示固定入口；键盘以贴靠右边缘的紧凑辅助抽屉打开，不改变当前题目或页面进度。
- 抽屉不显示全屏遮罩、不模糊背景、不锁定页面滚动，也不推动主内容；打开后仍可查看和操作底下的核心玩法。
- 当前接入加减练习、算数大战、乘法小能手、找数字、猫鼠游戏和知识币目标余额输入。
- 神秘函数参数、年龄、家长密码以及其他非答案字段不消费全局数字提交。

## 2. 输入和位值

- 底部固定提供 `0—9` 十个按钮；每次点击把数字追加到右侧，例如 `1 → 12 → 123`。
- 单独输入多个前导零时保持为 `0`；`0` 后输入非零数字时归一化为该数字。
- 最多输入 12 位非负整数，覆盖“个、十、百、千、万、十万、百万、千万、亿、十亿、百亿、千亿”。
- 每个数字格上方展示对应位值，数字下方同时展示完整中文读法。
- “清空”删除当前全部数字；“提交这个数字”只在已有数字时可用。

## 3. 统一提交协议

键盘通过浏览器内事件 `mumu:numeric-keypad-submit` 提交：

```ts
type NumericKeypadSubmission = {
  digits: string;
  value: number;
};
```

当前路由只允许一个活动接收者。各玩法必须把 `value` 交给已有业务函数：

- 加减练习：`acceptAnswer`，保留首次正确证据、反馈、奖励和切题语义；
- 算数大战 / 乘法小能手：在未解题中按唯一答案匹配，复用点亮、间隔计时与奖励；
- 找数字：结合当前选择的精确、小于或大于关系形成正式提问，范围外值不静默改写；
- 猫鼠游戏：复用 `1—200` 整数校验、反馈、揭示和奖励；
- 知识币管理：只填入目标余额，仍需家长密码和显式确认才写入服务端。

没有活动接收者时，提交不得猜测页面上的输入框，也不得修改任何数据。

## 4. 可访问性与状态

- 入口、数字按钮、清空、提交和关闭均不小于 `48 × 48px`，支持键盘与可见焦点。
- 面板使用带标签的 `aside` 辅助区域和实时状态播报，不使用模态语义；支持关闭按钮及 `Escape`，打开时不强行抢走当前题目焦点。
- 桌面面板宽度约 300px，手机约 236px；长位值行只在自身内部横向滚动。提交成功后面板保持打开并清空数字，便于连续答题。
- 空输入、达到最大位数、清空和提交均有文本状态；不只依赖颜色表达。
- `prefers-reduced-motion` 下移除非必要过渡和动画。

## 5. 测试基线

- 连续追加、前导零、12 位上限与非法数字拒绝；
- 个至千亿位值映射；
- `0 / 12 / 123 / 10005 / 100000 / 100000001` 等中文读法；
- 五个正式数字玩法使用原有业务流程消费提交；
- 知识币目标值仍需服务端密码校验，键盘本身不能绕过权限。
