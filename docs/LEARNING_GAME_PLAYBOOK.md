# 木木学习岛：玩法总规则与扩建蓝图

状态：**正式生效**

更新时间：2026-07-31

本文把历次需求中反复出现的产品原则、已经完成的玩法语义、原有占位玩法和本轮新增玩法整理成一套可持续扩展的规则。专项玩法仍以各自文档为准；新增短任务玩法统一遵循本文和 [`DESIGN_SYSTEM.md`](./DESIGN_SYSTEM.md)。

## 1. 木木的学习体验

### 我们在训练什么

1. **努力和复习**：强调“多观察一次就多发现一点”，不把天生聪明、排名或速度当作价值判断。
2. **数感和原子能力**：基础算术追求稳定与熟练，复杂算术追求思考和挑战，两者不能混成一种玩法。
3. **语言表达**：孩子不会打字，主要任务必须能用大触控按钮完成；适合语音的玩法同时提供全程语音控制。
4. **科学好奇**：先让孩子观察现象、做出预测，再给出准确解释；虚拟演示不得伪装成真实实验步骤。
5. **知识连接**：结果不是只有对号，还要回答“为什么”和“它在生活中在哪里”。

### 一局的共同节奏

```text
选择少量配置
  → 明确这局要发现什么
  → 一次只完成一个核心任务
  → 温和反馈并保留再次观察机会
  → 显示准确的知识解释
  → 孩子主动进入下一题
  → 用学习星图总结本局发现
```

- 常规短任务提供 5 / 10 题；沉浸式专项玩法可按自己的文档提供其他数量。
- 不使用强制倒计时、生命值、连败、红色闪屏和羞辱性反馈。
- 正确后不自动跳题，给木木留出阅读知识卡的时间。
- 第一次没有选中正确答案，只标记为“观察后发现”，结算不出现“错题”。
- 中途结束只总结已经完成的发现，不伪装为完整通关。

## 2. 语音、朗读与手动操作

- 实时语音统一复用阿里云 Fun-ASR 的同源安全转接，密钥只存在 Git 忽略的本机配置文件中。
- 每段 ASR 强制最多 120 秒。到时保留当前状态，显示“继续识别”；除专项规则外不自动连续消耗下一段。
- 统一命令为“开始 / 下一题 / 再听一遍 / 结束 / 继续识别”，选择题支持“第一个 / 第二个 / 第三个 / 第四个”和直接说候选项。
- 只有最终识别句执行命令，中间结果仅用于轻量复述，避免增量和全量结果被重复消费。
- 文字朗读统一复用 `apps/web/src/shared/speech/`。朗读与 ASR 必须半双工：先停麦克风，再朗读，朗读完成后才新建识别会话。
- 语音不可用、未配置或到达上限时，按钮和键盘必须仍能完成全部核心玩法。

## 3. 数据边界

- 默认课程、题库、元素、分子结构和公开知识内容属于 `content/` 或源代码中的版本化内容，不包含儿童个人信息。
- 答题历史、掌握状态和家长设置属于 `var/` 中的运行时个人数据，必须原子写入、schema 校验并被 Git 忽略。
- 开放式探索和本轮短任务默认不写入个人数据；只有明确设计了长期复习价值的玩法才增加历史文件。
- 未完成的一局不写入“完成成绩”。可以仅在内存中保留本页状态。

## 5. 本轮补齐的原有玩法

### 化学：实验大师

- 定位：安全的“先预测、再解释”虚拟实验观察，不提供家庭可执行的化学步骤。
- 内容：溶解、过滤、蒸发、密度分层、酸碱指示、气体性质、结晶、温度影响等基础现象。
- 交互：观察舞台给出器材和现象，孩子选择预测结果；部分任务把观察顺序排成轨迹。
- 安全：危险材料只做知识解释，不提供用量、温度、压力或操作条件。

### 化学：物质虚拟世界

- 定位：从粒子视角理解固体、液体、气体、熔化、凝固、蒸发、凝结和扩散。
- 交互：舞台以实时粒子密度和运动状态表现物态，孩子根据排列与运动判断状态或变化。
- 重点：持续说明“粒子本身没有消失，只是距离和运动发生变化”。

### 英语：单词轨道

- 定位：用高频具体名词和动作词建立“英文声音—拼写—含义”的第一连接。
- 交互：大号英文词、读音、中文含义和概念图共同呈现；选择任务不要求孩子打字。
- 内容边界：首批聚焦颜色、数字、家庭、动物、身体和动作，不引入复杂语法术语。

### 物理：单位魔法

- 定位：先判断“该量什么”，再选择合适单位，不以机械换算作为唯一目标。
- 内容：长度、质量、时间、温度、容量和速度的日常量级。
- 交互：场景与刻度共同出现，孩子选择单位或比较量级；解释中给出生活参照。

### 宇宙：太阳系航线

- 定位：认识太阳系成员、行星顺序、昼夜与公转等基本空间关系。
- 交互：选择和排序结合；排序采用依次点亮轨道，不要求精细拖动。
- 准确性：明确太阳是恒星、月球是地球的天然卫星；模型比例是教学示意，不伪装成真实比例。

### 综合游戏：数字战争

- 定位：用“观察牌面—比较大小—选择策略”训练数感，不出现攻击、受伤和淘汰表述。
- 内容：数值大小、凑十、单双数、数列和简单心算。
- 反馈：把胜负改写为“哪艘数字飞船获得更多能量”，两边都保留在画面中。

## 6. 本轮新增玩法

### 数学：规律侦探

- 观察颜色、形状、数字与动作序列，找出下一项或缺少的一项。
- 规律只使用一种或两种可观察变化，避免依赖文字陷阱。
- 解释明确指出重复、递增、交替或镜像关系。

### 物理：力的实验舱

- 通过推、拉、摩擦、重力、磁力和弹性场景判断物体运动变化。
- 重点训练因果关系：“力可以改变速度或方向”，不把“正在运动就一定有向前的力”作为错误直觉灌输。

### 生命科学：人体探索站

- 认识心、肺、胃、脑、骨骼、肌肉和感官的基本作用。
- 不呈现诊断、疾病恐吓或医疗建议；解释使用孩子能理解的正常生理现象。

### 生命科学：细胞小宇宙

- 对比动物细胞与植物细胞，认识细胞膜、细胞质、细胞核、叶绿体和液泡。
- 图形是教学示意，明确真实细胞形状很多样；不把细胞器画面当作真实显微照片。

### 物理：光影追踪

- 认识光沿直线传播、遮挡形成影子、透明/半透明/不透明材料和镜面反射。
- 舞台通过光束、物体和投影位置的变化帮助孩子观察，不使用频繁闪烁。

## 7. 内容质量门槛

- 每个短任务玩法至少提供 10 个互不重复任务，足够支撑 5 / 10 题两档。
- 每题必须包含：明确问题、可操作候选项、唯一答案、具体提示、准确结论、儿童可理解的解释、视觉观察信息和语音别名。
- 科学知识优先使用稳定的教材级事实；存在比例、模型或简化时明确写“示意”。
- 禁止为了增加数量而编造实验现象、化学结构、人体功能、天文数值或词语读音。
- 单元测试至少覆盖课程数量、ID 唯一、答案合法、排序完整、语音选择解析和抽题不重复。

## 8. 后续扩展办法

1. 先确认新玩法是否需要沉浸式专项界面；只有短任务型知识卡才复用多学科探索任务舱。
2. 新任务数据先经过结构校验，再进入课程库；不要把业务规则散落在 JSX 中。
3. 需要长期复习时，再为该玩法设计独立 schema 和 `var/learning/...` 文件，不默认混用其他玩法成绩。
4. 出现新的通用交互时，先更新 `DESIGN_SYSTEM.md` 和本文，再扩展正式组件。
