# Mumu 学习岛设计系统

状态：**正式生效**

视觉基线：`temp/style-02-galaxy.html`（星际探索舱）

适用范围：儿童学习端、家长端、管理与导入导出界面、后续新增的全部 Web UI

## 1. 一句话定义

这是一个为 5 岁孩子准备的 **明亮、安全、充满探索感的星际学习舱**：深蓝宇宙作为安静背景，紫、青、粉的发光色作为任务和反馈信号，圆润的大尺寸组件让孩子像操作飞船控制台一样完成学习。

界面要有“哇，想点一下”的活力，但不能刺眼、拥挤、闪烁或制造失败压力。

## 2. 设计目标与边界

### 必须做到

- 儿童第一：题目、答案和下一步操作永远最醒目。
- 星空沉浸：深色背景、柔和星点、半透明玻璃面板和有层次的彩色光晕。
- 大而清楚：儿童端正文不小于 18px，主要题目/数字通常为 44–82px，关键触控目标不小于 48 × 48px。
- 灵动而克制：交互有明确的按下、选中、成功和加载反馈；背景动效仅作陪衬。
- 家长不被排除：家长面板沿用同一套星际语言，但信息密度更高、层级更清楚、装饰更少。
- 可扩展：新增 UI 先成为设计系统中的组件模式，再进入业务页面。

### 不要这样做

- 不要引入第二套主视觉（纸艺、街机、糖果、拟物等），也不要在单页临时换浅色主题。
- 不要使用纯黑大底、刺眼荧光大面积铺满、频繁闪烁、自动播放声音或连续爆炸式庆祝。
- 不要只用颜色表达正确/错误/选中；必须同时有文字、图标、边框、形状或位置变化。
- 不要使用过小的文字、密集的图标墙、难以点击的文字链接或儿童不理解的技术词。
- 不要把 emoji 当作关键操作的唯一标签；emoji 只辅助文字和状态。

## 3. 视觉语言

| `--space-850` | `#171536` | 深层容器/页脚 |
| `--glass-700` | `rgba(28, 28, 66, 0.82)` | 主玻璃面板 |

| `--ink-secondary` | `#B8B7D7` | 辅助文字 |
| `--line-glow` | `rgba(202, 204, 255, 0.17)` | 边框、分隔线 |
| `--violet-400` | `#8D73FF` | 主操作、选中态 |
| `--violet-600` | `#6950DC` | 主操作按下/深色层 |

### 字体与文字

- 字体优先级：`ui-rounded, "Arial Rounded MT Bold", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 标题和数字使用 `--font-display`，字重 900–950、紧凑字距；正文使用清晰的圆体系统字体。
- 儿童端：页面标题 42–76px、区块标题 30–46px、题目数字 44–82px、正文至少 18px。
- 家长端：保持至少 16px 的辅助信息；数据和操作标签不能小于 14px。
- 文案简短、肯定、可行动：使用“再数一数”“我们一起试试”，避免“错误”“失败”“你应该”。

### 形状、材质与层次

- 主容器：半透明深蓝玻璃，`24–36px` 圆角，细亮边框，带轻微内高光和柔和深阴影。
- 主要按钮：圆角胶囊或 14–18px 圆角，紫粉渐变，按下时有明确下沉和暗色阴影。
- 输入框、选项与统计卡：玻璃次级表面，边框默认低对比；焦点/选中后改用紫色边框与轻微光晕。
- 允许使用低密度星点、行星、轨道、任务芯片等 CSS 形状或小图标；它们只能围绕内容，不能遮挡或抢夺题目。
- 不使用重型纹理、写实宇航图片或复杂 SVG 装饰来填充空白。

## 4. 组件系统（后续 UI 必须覆盖）

新功能不能只拼出“能用的控件”。凡是引入新的交互模式，都应先确定其在下列系统中的位置、状态和移动端表现。

| 组件族 | 至少包含的形态 | 视觉/交互要求 |
|---|---|---|
| 导航与任务 | 顶栏、返回、任务步骤、进度条、任务芯片 | 固定清晰的当前位置；不让孩子迷路 |
| 操作按钮 | 主、次、静默、危险、图标、加载、禁用 | 48px+ 高度；有 hover/pressed/focus/disabled；主操作紫粉渐变 |
| 表单输入 | 文本、数字、密码、搜索、下拉、日期/时间、滑杆 | 统一玻璃输入底；标签不只靠 placeholder；错误说明放在字段附近 |
| 选择控件 | 单选、多选、开关、分段按钮、筛选 chip | 选中同时改变边框、底色和勾选/状态图形；支持键盘 |
| 学习交互 | 数字键盘、拖放、排序、配对、填空、计时、提示、答案反馈 | 每个题型有开始、进行中、正确、可重试、完成五种体验状态 |
| 内容承载 | 卡片、面板、折叠区、标签、列表、空状态、骨架屏 | 信息先于装饰；空状态给出下一步，而非只有插图 |
| 数据展示 | 统计卡、进度环、柱图、趋势线、日历热力图、成就墙 | 图表同时给文字摘要和无障碍标签；不只用颜色区分数据 |
| 系统反馈 | toast、提示气泡、确认框、模态框、成功庆祝、错误提示 | 成功可有短暂星屑；错误温和、可恢复；破坏性操作必须二次确认 |
| 家长与数据 | 数据目录状态、备份、导入、恢复、设置、权限提示 | 保持星际视觉，但风险和后果要用明文说明；数据操作绝不伪装成儿童任务 |

组件的最小状态集：`default / hover / pressed / focus-visible / disabled / loading / success / error / empty`。不适用的状态必须在组件文档中说明原因，而不是忽略。

### 学科探索板块

- 首页的学科入口采用“左侧学科舱 + 右侧玩法星块”的布局。每一行是一门学科；学科舱负责说明方向，玩法星块负责承载具体游戏。桌面端每一行的玩法区固定为 **3 个等宽星块**，不足三个时保留自然留白；不在单行内混用大小不一的卡片。
- 学科舱使用一个低密度、CSS 绘制的学科符号（例如函数曲线、分子节点、摆锤、行星环）作为辅助插画；文字始终是辨识学科与玩法的主要方式。
- 玩法星块最小高度为 92px，必须具备 `default / hover / pressed / focus-visible / disabled / empty` 状态。已实现玩法使用可点的大触控卡；尚未定义的学科显示一个明确的“正在准备”空状态，不伪造可用入口。
- 学科行之间可通过色彩、学科符号和轻微装饰体现探索感，但不允许遮挡、重叠文字或让装饰压过游戏名称。移动端改为一列顺序流，每个学科舱后紧跟其玩法星块。
- 悬停与按下只产生轻微上浮、边框高亮和光晕变化；不得使用频繁闪烁或大幅位移。所有效果必须服从 `prefers-reduced-motion`。

### 沉浸式逐题练习页

- 页面由“顶部任务驾驶舱 + 中央演算舞台 + 次要状态区”组成。配置和历史入口留在顶部；演算舞台始终只突出当前题目、答案反馈和一个主要操作，不把统计数据挤进儿童的计算视线。
- 顶部配置使用带文字标签的分段按钮。选中态必须同时出现高亮边框、填充和勾选标记；任务进行中锁定配置，并用禁用样式说明“本局结束后可调整”，避免误触改变本局口径。
- 题目数字使用显示字体和高对比亮色，桌面端建议 `clamp(64px, 12vw, 150px)`；背景插画只布置在四周并为中央题目保留低细节、低对比的安全区。
- 语音状态使用不抢焦点的小型胶囊：`准备中 / 正在听 / 朗读中 / 已到本次上限 / 需要配置 / 连接失败`。状态同时包含文字与图形，不用闪烁红点制造紧张感；到达 ASR 上限时给出清楚的“继续识别语音”按钮。
- 答案反馈分为两级：正确时显示“答案 + 对号”和不超过 2 秒的柔和星光；首次命中错误答案时显示“答案 ? / 再想一想”，演算与语音不中断，不显示失败、扣分或倒计时。
- 历史成绩属于家长信息层，使用覆盖式玻璃子面板或侧边抽屉。必须提供聚合条件、场次、总耗时、单题平均耗时、计算时间、年龄和正确率的文字摘要；空、加载、错误均给出明确状态。
- 结果页逐题列出算式和“第一次就答对 / 想过一次后答对”，并提供一个大号“再来一局”操作。正确率按题目是否曾命中过错误答案计算，不能因最终答对而覆盖本题的首次错误标记。
- 音效只能由儿童主动开始一局后启用；成功音短促清亮，语音朗读遵从页面配置。必须支持静音选择和 `prefers-reduced-motion`，不得自动循环背景音乐。

### 动态看图列式解谜页

- 适用于“猫鼠游戏”等通过角色、场景、参照物和测量标记组织应用题的玩法。进入页面后立即显示一道完整题目，不增加阻挡题目的配置页；题目舞台、已知线索、答案输入和温和反馈必须出现在首屏主要阅读流中。
- 场景背景可以随机变化，但只能作为低对比环境层。角色、道具、测量箭头、数值标签和组合关系必须分层渲染，文字与数值由真实 HTML 绘制，不烘焙到图片中。透明精灵必须保留清楚轮廓，不能带绿幕色边、图集分隔线或不相关投影。
- 每题允许在高度对比、上下叠放、重复分组、平均分配和等量关系等布局中切换；布局变化不能改变“图片舞台在前、答题区在后、解法在结果中”的认知顺序。相同对象的尺寸、基线和堆叠接触点要稳定，测量标记不得被角色遮挡。
- 作答前只展示故事、图片和已知数值，不提前暴露完整方程。正确作答或孩子主动选择“看看怎么列式”后，再依次展示图片对应的原始方程、逐步变形和带单位的具体答案。
- 答案输入只接受题目声明范围内的整数。非法输入、再次尝试、正确、主动揭晓、资源缺失和生成失败都要有文字状态；再次尝试不使用“失败”“扣分”或红色闪烁。换题操作至少 48px，并保证新题的数值、场景或布局与当前题不同。
- 桌面端可采用“左侧大图片舞台 + 右侧解题舱”；移动端改为单列，图片舞台在上、输入与解法在下。移动端可以把双场景改为上下两格，但不能缩小到看不清角色、参照物和数值标签。`prefers-reduced-motion` 下移除卡片错位、入场位移和成功弹跳，仅保留静态状态变化。

### 并行多题挑战页

- 适用于“算数大战”“乘法小能手”等需要同时观察多道题、自由选择解题顺序的玩法。顶部仍使用任务驾驶舱；中央演算区固定为 1–5 个纵向题目行，每题独占一行，不使用多列网格或大块卡片。
- 题目行使用轻量分隔线组织信息，不设置厚重面板背景。序号位于左侧，算式占据中央主要空间，完成状态和耗时位于右侧；窄屏时状态可换到算式下方。
- 算式必须完整显示，优先使用单行和自适应字号；极窄屏允许整条题目横向滚动，但绝不能把相邻题目互相遮挡或裁切。
- 未完成行显示 `算式 = ?`；命中唯一正确答案后，以对号、答案、柔和绿光和本题耗时共同进入完成态。完成行仍留在原位，不打乱其他题目的空间记忆。
- 非命中结果不是“答错”或扣分，只在演算区边缘显示短暂结果气泡：`= 结果` 与“这个结果不是任何一个题的答案，请再算算”。气泡 3–4 秒自动消失，不遮挡题目，也不计入正确率。
- 分段语音使用 `第 n / 5 段 · 每段最多 2 分钟` 的小型状态芯片。每段到时后显示明确的“继续识别”操作；五段用完仍未完成时进入温和的挑战暂停页，不生成完成成绩。
- 结果页按实际解出顺序展示每题耗时：第一题从任务开始计时，之后各题采用相邻两个正确答案之间的间隔。全部解出才显示 100% 完成和保存历史，不使用“错题数”“扣分”或失败措辞。

### 全宽科学图谱与元素详情

- 适用于“元素周期表”等需要同时观察大量科学对象与空间关系的页面。页面主体使用接近视口全宽的工作区，保留 18 族、7 周期以及镧系/锕系的标准空间结构；桌面端优先完整展示，窄屏允许整个图谱水平滚动，不压缩到无法辨认。
- 科学图谱页必须让主图谱尽早出现在首屏。元素周期表标题区只保留紧凑的“元素周期表”标题，不使用大段品牌话术、说明面板或重复语音状态占据主表空间；语音状态收纳在顶栏入口。
- 元素格必须同时显示原子序数、元素符号、中文名、拼音和相对原子质量；分类不能只依赖颜色，还要通过图例名称、格子边缘标记和无障碍标签共同表达。
- 面向儿童查阅时，元素格内中文名是主要阅读信息，字号不得小于 18px；元素符号保持清晰但不压过中文名。调整文字层级不得改变标准元素格尺寸或周期表空间结构。
- 默认选中原子序数 1。点击、键盘方向键和语音“上/下/左/右”共享同一套空间导航规则：寻找目标方向上最近的实际元素，不把周期表空位当作可选节点；到达边缘时停留。选中态使用高亮边框、柔和光晕和位置稳定的焦点标记。
- 语音“详细信息”打开当前元素，“返回”关闭详情或返回首页。语音状态保持次要，不覆盖元素格；每次会话仍遵守服务端 2 分钟上限，并提供明确的继续识别按钮。
- 元素详情使用接近全屏的大型玻璃弹窗。桌面端左侧为粘性原子观察台，右侧为可滚动资料区；弹窗滚动时原子模型保持在视野内。移动端改为上下排列，不强行粘住模型。
- 原子模型按电子层数据动态渲染，不为 118 种元素制作静态截图。原子核居中，由互相挤压、轻微形变的质子/中子球组成；前 10 个元素按质子数与估算中子数逐个展示，后续较重元素允许使用保持质子/中子比例的密集核团示意。元素符号与核电荷数字必须稳定正向，不跟随核子团旋转。
- 电子轨迹本身固定不动，电子沿轨迹运行，不能通过旋转整条轨道制造假运动。每层可以使用不同速度和相反方向；电子中心必须始终落在对应椭圆轨迹上，并使用“圆圈 + −”图形表达负电荷。内层电子使用低饱和灰蓝，最外层使用明亮青/粉，配合文字明确说明电子层分布。
- 详情资料至少覆盖物理性质、化学性质、电子排布、发现信息、自然存在/来源、典型用途和常见化合物。未知或仅有预测值时必须明确标注“未知/预测”，不得为了丰富而虚构。
- 元素详情中的化合物目录使用“可搜索分页清单 + 当前物质档案”双栏模式：清单按钮至少 64px 高，显示化学式、中文名和类别；档案同时展示本地二维结构图、球棍/组成示意、具体组成、属性、观察要点、安全说明和来源。窄屏改为清单在上、档案在下；无数据、无搜索结果、上一页/下一页禁用和图片缺失都要有明确状态。
- 弹窗必须有可见关闭按钮、焦点圈、`Escape` 支持、标题关联和滚动边界；支持 `prefers-reduced-motion` 时停止轨道旋转，仅保留静态电子位置和选中状态。

### 全屏拼音总表与汉字详情舱

- 适用于“拼音星桥”等需要在一个入口内浏览完整学习单元集合的页面。整体沿用全宽科学图谱的“顶栏 + 总表 + 覆盖式详情”结构，但拼音分区按儿童教材语义组织为 `23 个声母 / 24 个韵母 / 16 个整体认读音节`，不能按技术字符串或随机顺序堆放。
- 桌面端三个分区必须在同一视口内完整出现；每个拼音格保持至少 48 × 48px，使用大号拉丁字母、中文分类标签、选中描边和位置稳定的焦点标记。页面主体锁定在一个视口内，不要求儿童使用鼠标滚轮上下翻页。
- 当屏幕不足以同时容纳三个分区和 48px 触控目标时，改为顶部三段式分区切换，一次展示一个完整分区；这属于同一张拼音总表的响应式视图，不把拼音拆成需要纵向滚动的长列表。分区按钮同时显示名称和数量，选中态不能只靠颜色。
- 点击、`Enter`、键盘方向键与语音方向命令共享同一套选中状态。语音至少覆盖“上 / 下 / 左 / 右”“声母区 / 韵母区 / 整体认读区”“详细信息”“换一批汉字”“关闭卡片”“返回首页”；中间识别结果只复述，最终句才执行打开、换批和返回等离散操作。
- 汉字详情使用适配当前视口的大型玻璃弹窗，不出现内部纵向滚动条。桌面端汉字卡按 `3 列 × 2 行`，窄屏按 `2 列 × 3 行`；极矮屏允许减少辅助说明或组词数量，但不能裁掉汉字、完整带调拼音、当前拼音高亮和至少一个组词。
- 每次打开或执行“换一批汉字”时，从该拼音的合法候选字池中随机选择且不重复的汉字。每张卡必须展示大字、完整带调拼音和相关组词；当前声母、韵母或整体认读音节在完整拼音中使用高亮底、加粗和下划线共同标记，不能只改变颜色。
- 详情弹窗提供可见的“换一批”和“关闭卡片”按钮，支持 `Escape`，打开后把焦点移到关闭按钮，关闭后把焦点还给原拼音格。背景不可操作；没有足够候选字时显示已有内容和明确空位说明，不伪造汉字或组词。
- 拼音页不自动播放声音、不记录学习成绩。语音不可用时，点击、触控和键盘仍能完成所有核心操作；ASR 会话继续继承服务端 2 分钟强制上限。`prefers-reduced-motion` 下取消弹层位移、选中脉冲和星点闪烁，只保留显隐、边框、文字和静态光晕。

### 实时反应熔炉

- 适用于“反应熔炉”等把多个原子逐步组合成分子或物质结构单元的互动页面。桌面端使用“左侧大反应场 + 右侧原子仓”的双栏结构，反应场必须明显大于控制区；移动端改为上下排列，原子仓不能遮挡反应场。
- 反应场使用 Canvas 实时渲染布朗运动、背景流体扰动、波纹和连接闪光，不用静态贴图伪装运动。空状态、原子游离、正在聚合、稳定结构和全部完成必须有不同且可读的视觉状态。
- 原子仓按钮同时显示元素符号、中文名、剩余数量和本次投放数量。少量原子按单个按钮投放；同种原子数量较多时允许按 10 个一组投放，但按钮仍要明确写出 `×10`，不能让孩子猜测。
- 达到目标配方后，相关原子按“靠近 → 高频轻微震动 → 键位闪光 → 稳定”的顺序完成组合。单次闪光不超过约 500ms，不使用全屏爆闪；稳定结构旁显示分子式、中文名和一句特性。
- 每批固定 10 个随机目标，其中有机物严格为 2 个、无机物为 8 个。选择器先随机确定 10 种优先元素，再选择覆盖全部优先元素的相关化合物，并保证最终至少出现 10 种元素；整批原子总量设置明确上限，避免有机物占满一批或大量粒子拖慢儿童设备。桌面反应场把 10 个稳定结构放入 5 列 × 2 行的固定停泊位；窄屏改为 2 列 × 5 行。新结构以极低速、带轻微布朗扰动的方式归位，抵达后只在本槽位附近微幅漂浮，不得跨槽重叠。
- 常见元素使用跨反应场、原子仓和星图一致的领域色：H 淡蓝 `#B8E8FF`、C 中黑 `#4F5565`、N 深蓝 `#3657C8`、O 深绿 `#168F5F`、Na 深红 `#A93A4E`、Ca 浅红 `#FF9AAE`、F 浅紫 `#C7A7FF`、Cl 深紫 `#6E3BAA`、S 黄色 `#F3D44E`、K 橙色 `#F39A38`。深色球体保留白色高光、亮边和白色元素符号；颜色用于帮助快速辨认，但不能单独表达元素身份。
- 次要星图清单中的每个目标与反应场停泊位一一对应；完成后同时显示对号、分子式、文字状态和静态结构缩略图，未完成时不能伪装为已有结构。具有权威连接拓扑的离散分子以实线显示球棍结构；离子晶体、盐和水合物可以用虚线连接原子球，但必须在同一视区明确说明“虚线是组成示意，不代表共价键”，并使用“结构单元/配方单元”而非强行称作孤立分子。无限晶体、石墨烯和碳纳米管只显示有来源的有限代表片段，并在文案中标注代表性原子数。
- 所有模拟必须明确为“虚拟组成演示，不是实验步骤”。不得提供危险物质的制备条件、用量、温度、压力或可操作流程。
- 减弱动效模式下停止持续布朗运动和背景扰动，投放原子保持静态散布；聚合使用短暂淡入和边框高亮替代震动、强闪光和大幅位移。

### 开放式分子工厂

- 适用于“分子工厂”等由孩子自由选择元素、持续投放原子并收集组成结果的开放探索页。桌面主体沿用“左侧大反应区 + 右侧密集元素表”，顶部导航保持紧凑，只保留返回、玩法名、核心计数、合成选项和重置操作，不设置大标题区抢占反应空间。
- “不创造有机物”“自动合成”使用大号勾选控件，选中态同时出现勾选、亮边和填充，聚合期间显示禁用态。桌面端并排放入顶栏，空间不足时整体换到第二行，不能压缩到文字不可读。
- 元素选择器展示原子序数 1—90，按原子序数使用每行 9 格的连续紧凑网格，不保留标准周期表空位。每格显示原子序数、横向并排的元素符号与中文名，以及淡化的“已收集物质数 / 当前游离原子数”；中文名是格内主要阅读信息，在 60px 元素格中使用约 26px，元素符号约 16px，并压缩内边距使文字几乎填满方格。元素符号要使用与深色背景有高对比度的明亮元素色，并保留柔和发光，避免深色元素符号造成儿童阅读疲劳。新增计数不得增大元素格高度或推动整体布局，选择器只允许自身纵向滚动。
- 点击元素格既投入原子，也把该元素设为当前查看对象。氢和碳每次投入 5 个，氧每次投入 3 个，其他元素每次投入 1 个；批量规则不增加格内标签或改变元素表布局。元素网格下方列出本轮已收集且包含该元素的物质；列表为空时给出明确空状态。每条记录提供带“×”与“移除”文字的 48px 触控操作，移除后同步更新元素计数和成品收藏架，并允许该物质重新合成。
- 游离原子继续复用反应熔炉的领域色、元素符号、入场扩散、布朗运动与边界碰撞，但分子工厂中的位移速度固定为反应熔炉的 50%，给儿童留出观察组成的时间；当前组成和数量必须有可见文字摘要，不能只在 Canvas 中表达。
- 自动合成关闭时，在原子运动区底部同时展示最多 3 张可合成提示卡。卡片使用较宽、较矮的横向布局，只包含大号化学式和中文名，不重复显示“点击合成”；约 5 秒低速漂浮并淡入淡出，整张卡仍是可点击的 48px+ 触控目标。忽略后立即轮换下一批当前可合成物质，有足够候选时避免与上一批重复；持续轮询直到没有候选、切换到自动模式或开始聚合。减弱动效模式下卡片静止，但保持同样的可见时长和操作能力。
- 已形成原子团不使用右上角面板。每类原子团在 Canvas 中以一个复合粒子持续漂浮，粒子本体明确显示标准原子团式和电荷；左上角组成摘要同时把它作为 `原子团式 ×1` 列出。原子团形成时必须让对应游离原子逐渐靠近并扣除，之后作为可消费的完整中间库存参与化合物；若化合物需要多份同类原子团，只使用界面上的一份完整原子团，其余用散装原子补足。
- 原子团和化合物共享串行构建队列，一次只构建一项。原子团使用紫青能量环、少量星点和稳定闪光突出“特殊伙伴”的形成；化合物按“完整原子团/散装原子靠近 → 震动 → 键位发光 → 稳定 → 向底部离场”的顺序组成，并以可读状态卡显示当前队列项。成品收藏架必须紧贴在反应区正下方，离场结构直接落入收藏架；反应区高度应为初版紧凑布局的约 80%，优先让收藏架标题和最新结果在首屏露出。
- 同一物质本次探索只出现一次；桌面成品收藏架使用每行 3 张卡片的网格，最新生成的卡片固定在左上角第一位，已有卡片依次向右、再向下一行后移。每张卡片展示发现序号、结构、分子式、名称、特性与“已收藏”；窄屏降为单列。空收藏架给出一个低压力起步建议，不直接铺开全部答案。
- 单原子单质不触发收藏，多原子单质可以触发。页面持续标注“虚拟组成演示，不是实验步骤”，不展示任何可执行的危险物质制备条件。
- “清空原子和原子团”同时清空游离原子与原子团并保留成品收藏架，“重新开始”清空全部当前探索；两者必须有明确文字且在构建期间正确禁用或保护状态，移动端也不得隐藏清空入口。移动端改为反应区、元素表、成品收藏架的纵向顺序；减弱动效下使用静态光环、静态散布与短淡入淡出。
- 分子工厂与反应熔炉恢复本设备上一次探索时，恢复的已合成结构、游离原子数量、原子团和清单必须直接呈现为既有状态，不播放补造成功动画，也不用弹窗抢占反应区；若本地缓存不可用，仍从清晰的空状态正常开始。

### 互动函数图像实验室

- 适用于“神秘函数”等让孩子同时观察公式、参数和图像变化的开放式探索页。桌面端采用“顶部任务栏 + 中央大坐标舱 + 右侧公式与参数舱”，坐标图必须占据首屏主要面积；移动端按坐标图、已选曲线、参数控制、公式库的顺序纵向排列。
- 一次最多展示四条曲线。每条曲线使用稳定的颜色、编号和公式名称，选中态同时加粗曲线、提高光晕并在列表中出现“正在调整”文字；不能只靠颜色区分。新增第五条时不覆盖现有曲线，而是提示先收起一条。
- 公式库以儿童可理解的模板卡展示一次、二次、三次、正弦、余弦、绝对值、平方根、反比例和指数函数。卡片同时给出标准公式和一句图像特征；加入后自动成为当前曲线，并给出可以立即观察的安全默认参数。
- 参数使用带文字含义的减号按钮、直接数值输入和加号按钮共同控制，按钮步进固定为 `0.5`。除数学定义域与极大有限值安全边界外不设置日常可见的小范围限制；参数变化必须在下一绘制帧即时更新公式和完整曲线。
- 坐标舱必须有清晰的网格、带数字刻度的 x/y 轴、原点和可直接输入的当前可见范围。缩放按易理解的 `1 / 2 / 5` 量级跨越小数到大数，网格密度不能随范围线性增长。曲线越过定义域或出现渐近线时分段绘制，不把不连续的两端错误连接；任何数学异常仅跳过该采样点，不能让整个页面失效。
- 每次新增或切换曲线后，使用“从左到右逐段点亮 → 少量粒子沿曲线汇聚 → 整条曲线稳定发光”的短动画帮助孩子看见变化。动画不超过约 300ms，不连续爆闪；连续调参和缩放直接重绘，不能反复等待动画。其余未选曲线保持低一层亮度，避免四条曲线互相抢夺。
- 坐标探针允许点击或拖动图像，显示每条可计算曲线在同一 `x` 位置的 `y` 值，并用垂直虚线关联位置。数值仅作为观察工具，不自动判定对错，也不制造倒计时或分数压力。
- 页面必须提供开始介绍、随时重置、删除单条曲线、结束探索和返回首页。结束页用文字总结本次观察过的公式、最终参数与探索数量，提供“继续探索”和“再开一次”操作；当前版本不写入儿童个人数据。
- `prefers-reduced-motion` 下曲线直接完整出现，关闭粒子飞行、扫描光和持续呼吸，只保留选中粗细、颜色、文字和静态光晕变化。Canvas 还必须提供等价的文字曲线列表与实时公式，不能把关键信息只画在位图中。

### 二分找数字探索舱

- 适用于“找数字”等通过连续比较缩小整数候选范围的数感玩法。开始页先选择 `0—100 / 0—1000 / 0—10000 / 0—100000`，进行中始终只随机一个包含两端点的整数目标；目标在通关前保持隐藏。
- 页面核心是持续存在的数轴。开局和候选区较宽时展示完整范围；候选跨度不超过完整范围约 `18%` 时，数轴以约 `620ms` 平滑聚焦到带上下文留白的局部范围，并明确标记“局部放大”。候选区两端必须保持可读间距，不能像素级挤在一起；仍可能存在目标的区间使用青粉发光带，已排除区使用灰色“星尘冻结带”、斜纹和碎裂纹理共同表达。
- 每次比较后只让“本次新排除”的数轴区段播放不超过约 850ms 的暗化、裂纹和少量星屑消散，既往排除区保持稳定灰暗。不能用全屏爆闪、红色失败带或让整条数轴抖动。
- 语音问句至少支持“是 500 吗 / 小于 800 吗 / 大于 300 吗”，并可兼容“不超过 / 至少”等边界表达。页面用大字同时复述听到的问句和结论，例如“神秘数字比 500 大”，不能只移动图形而不解释。
- 每次有效提问都进入时间顺序记录，显示提问内容、判断结果、本次新排除数量、累计排除数量和提问时刻。重复或范围外提问仍保留，但明确显示“这次没有新排除”，不羞辱、不扣分。
- 进行中不显示候选中点、不估算还需几步、不自动把推荐数字填入输入框，也不提供一键提交推荐问题；孩子根据数轴与回答自己决定下一问。页面不得用步数排名或倒计时制造压力。
- 语音控制覆盖“开始一局 / 结束一局 / 下一局（再来一局）”。语音不可用时必须保留关系选择、数字输入和提交按钮；单段 ASR 仍强制最多 2 分钟，到时保留完整进度并提供“继续识别”。
- 精确命中后先保留猜题舞台：目标位置发出克制星屑，神秘数字从数轴原位弹起并稳定停留，再通过共享数字过渡进入结果页，不能瞬间替换整套界面。结果页列出总提问次数、每次数字、每次新排除数量、总耗时和完整过程。主动结束则温和揭晓数字但不伪装为通关；两种结果都提供“下一局”和“换范围”。
- 移动端保持数轴可横向完整观察，记录列表移到数轴下方，手动输入控件纵向排列且触控目标不小于 48px。`prefers-reduced-motion` 下直接切换冻结/可行区状态，关闭裂纹扩散、星屑和目标脉冲。

### 单屏大字识字星图

- 适用于“常用 500 / 1000 / 1500 / 2000 / 2500 字”等逐字阅读玩法。桌面学习态必须锁定在一个视口内，使用“顶部轻量进度 + 中央识字舞台 + 底部动作”的单一路径，不要求儿童滚动才能看完当前字。
- 汉字是绝对视觉主角，使用楷体优先的字体栈和 `clamp(155px, 16vw, 245px)` 尺寸；拼音居于汉字上方，部首和笔画作为低干扰胶囊信息。星轨、粒子和网格只环绕大字，不能穿过字形或影响辨认。
- 内容按“汉字立即出现 → 约 1.7 秒出现拼音 → 约 3.9 秒出现释义、组词、例句和成语”渐进揭示。手动“看拼音和词语”与语音“详细信息 / 看看拼音 / 提示”可立即完成揭示；减弱动效模式只改变显隐，不使用位移、模糊或持续呼吸。
- “我会了”使用绿色对号、文字标签和短暂稳定光晕共同表达，只标记当前字而不强制跳题；没标记的字使用“继续复习 / 以后还会见面”，不得写成错误、失败或扣分。
- “下一个”是底部最醒目的紫粉主操作；“我会了”是绿色次主操作；揭示和结束属于低层级玻璃按钮。所有按钮必须具备 48px+ 触控高度、键盘焦点、禁用和按下状态。
- 语音状态保持在顶栏右侧，提供 `识别中 / 已暂停 / 已到 2 分钟 / 未配置 / 连接失败` 的文字和圆点状态。ASR 结果仅在轻量状态行复述，不在大字上方弹出遮挡层。
- 结算页只总结“学过 / 我会了 / 继续复习”，不用正确率。逐字结果同时展示大字、拼音和状态文案；五字局桌面可一行展示，十字局自然换成两行。
- 全量文字清单属于覆盖式大玻璃面板，按频率顺序展示学过次数、我会了次数和继续复习次数。它支持搜索、状态筛选和分页，不能一次渲染 2500 个复杂行；状态必须用圆点、颜色和文字三者共同表达。

### 虚拟实验观察任务舱

- 适用于“实验大师”的短观察任务。共享“启程配置 → 观察舞台 → 儿童操作 → 知识解释 → 本局星图”的流程，每个任务根据知识本身选择单选或顺序选择交互，不能只替换题干。
- 启程页只配置 `5 / 10` 个任务和朗读开关；不显示难度排名、倒计时或分数压力。页面需要说明“这次会发现什么”，并列出三项具体能力目标，不用空泛的闯关话术。
- 进行页保持单屏核心任务：顶部显示返回、进度、语音和朗读状态；中央视觉观察台使用 CSS 图形、文字、轨迹、刻度或实时状态组合解释概念，不用无含义的装饰图占据主角位置。
- 选择任务的候选项必须至少 `64px` 高，使用编号、文字和选中形态共同辨认；排序任务采用“依次点亮”的轨迹，已选择项进入上方顺序槽，支持撤回和重新排列，不能要求五岁儿童精细拖拽。
- 第一次选择不合适时不立刻切题，保留观察舞台并提示一个具体观察方向，例如“看看哪种材料能被磁铁吸引”。同一题最后发现正确答案后，结果页写“观察后发现”，不写答错、失败或扣分。
- 正确后先展示一句结论和一段不超过约 60 字的知识解释，再由孩子点击“下一个发现”；不得在孩子读完前自动跳走。知识解释中的关键量、单位或词语使用高亮胶囊，但不能依赖颜色表达含义。
- 语音统一支持“开始 / 下一题 / 再听一遍 / 结束 / 继续识别”和“第一个 / 第二个 / 第三个 / 第四个”或直接说候选项。中间识别结果只能复述，最终句才执行选择；每次 ASR 最多 2 分钟，到时保留完整任务状态。
- 朗读必须复用通用 Web Speech 服务。启用自动朗读时，严格执行“停止 ASR → 朗读当前题目和候选项 → 朗读结束 → 新建 ASR”的半双工流程；切题、离页、重开后旧朗读不得重新打开麦克风。
- 本局星图展示“完成了多少个发现、第一次发现、观察后发现、遇到的知识卡”，不计算儿童能力排名。中途主动结束可以展示已完成发现，但不伪装为完整通关，也不写入学习成绩。
- 实验大师使用稳定的橙色辅助光与实验舞台图形；页面背景、玻璃材质、按钮、字体、反馈色、圆角和动效仍服从“星际探索舱”主视觉。
- 移动端按观察舞台、题目、操作、解释的顺序自然排列；任务关键内容无需横向滚动。减弱动效模式关闭轨道旋转、漂浮、扫描与粒子，只保留位置、文字、边框和显隐变化。

### 朗读控制与状态

- 题目、阅读材料和知识卡片统一使用 [`WEB_SPEECH_SYNTHESIS.md`](./WEB_SPEECH_SYNTHESIS.md) 定义的浏览器朗读能力，不在业务页面另建声音队列。
- 声音默认关闭，或只在孩子/家长明确选择朗读并开始任务后播放。页面加载、切换卡片或获得焦点本身不能触发声音。
- 短题目允许在孩子开始一局后按配置自动逐题朗读；长阅读必须提供带文字的“朗读内容 / 暂停 / 继续 / 停止”操作，主要触控目标不小于 48 × 48px。
- 状态至少覆盖 `准备朗读 / 正在朗读 / 已暂停 / 暂时不能朗读`。加载态可以使用低频静态或柔和进度图形；成功态不额外庆祝；错误态保留可见原文并允许再次尝试；空内容时禁用朗读并说明“这里还没有可以朗读的内容”。
- 播放、暂停和选中状态不能只依赖图标或颜色，必须同时有文字；按钮继续具备 `default / hover / pressed / focus-visible / disabled / loading / error / empty` 状态。不适用独立 `success` 视觉，因为朗读完成是正常结束而非学习成就。
- 句子级跟读高亮使用边框、柔和底色和文字位置共同表达，不使用逐字闪烁。朗读下一句时页面只能进行必要的小幅滚动，并尊重 `prefers-reduced-motion`。
- 同一页面使用语音识别时，朗读状态与“正在听”状态必须互斥；先完成或停止朗读，再打开麦克风，避免系统声音被识别成孩子回答。
- 浏览器或语言包不支持时显示温和的次要提示，不能遮挡题目、清空进度或把声音失败描述为孩子失败。

### 国学经典左右精读舱

- 适用于《声律启蒙》等需要同时阅读原文与理解注解的长篇经典。桌面端固定采用“左侧原文、右侧讲解”的双栏结构，两栏都允许独立滚动；原文栏略宽，当前句始终保持在舒适阅读区域。移动端改为“原文在上、讲解在下”，点击句子后把讲解滚动到可见位置，不使用横向滚动承载正文。
- 原文必须按章、按则、按句分层。句子是最小点击与朗读单位，按钮正文不小于 `22px`，拼音不小于 `16px`，整块触控高度不小于 `64px`。当前句同时使用左侧标记、柔和底色和“正在讲这一句”文字表达，不只改变颜色。
- 讲解栏使用稳定的四层顺序：“先懂意思 → 词语小卡 → 为什么这样对 → 典故小故事”。词语小卡必须把原文左右两边的词放在同一行，以“左词 对 右词”显示各自拼音和含义，不能留下只解释一边的孤立卡片。不向约五岁儿童展示平仄、词性、格律术语；没有专门典故时明确写“这句没有专门故事”，不得为凑内容编造典故。
- 全书目录必须区分“原文与精注”和“原文可读、注解待补”。未精注章节可以展示来源明确、已完成基础清理的公版原文并提供点读，但不得显示未经复核的拼音、释义和典故，也不能伪装成已经完成逐句精注；发现明显 OCR 错字时必须先更正再展示。
- 朗读提供“只读原文 / 原文和讲解”两种明确模式。声音默认不自动播放；孩子点击句子或“从头朗读”后才开始。全文朗读按句推进并同步高亮，支持暂停、继续和停止；切章、离页或点击另一句时立即停止旧队列。
- 讲解文案使用适合听的完整口语，不朗读控件名、章节状态或整页文字。历史典故要区分史实、常见解释与神话传说；遇到古代性别、战争、饮酒等语境时，用一句儿童可理解的现代说明消除刻板印象或模仿风险。
- 双栏面板继续使用星际探索舱的玻璃材质和紫、青、粉高光，但原文区域降低装饰密度，保证长时间阅读不刺眼。加载、无声音、空讲解和待校注状态都保留可读原文或明确下一步，不显示高压进度和失败反馈。

### 万物构成塔与符文关系图谱

- 适用于从粒子、元素、物质逐层探索到生活物品、工程系统、地貌、行星和宇宙的重型发现图谱。整体采用“顶部探索状态 + 左侧层级导航轨 + 中央连续符文图 + 右侧资源背包”。左侧导航是独立固定列，不参与中央节点的列数与居中计算；中央节点必须以导航右侧的剩余图形区域为中心。15 个层级是同一张图里的背景分带和定位刻度，不得做成切走整张图的 Tab、目录页或互相隔离的节点列表；移动端仍保留同一张可平移、缩放的连续图，再把资源背包排列到图谱下方。
- 图谱节点使用“独立外框 + 独立内容图 + HTML 文字”的三层结构。外框按普通、稀有、史诗、传说表达复杂度，不把选中、锁定或名称烘焙进图片。内容图可以是独立文件，也可以是固定网格图集中的精确裁切；选中放大必须继续使用同一高清格位，不能换成模糊缩略图。没有通过语义校验的专属内容图时使用星尘纹理和节点自身名称占位，层级主题图只用于左侧层级导航，不能冒充具体节点，避免出现“图很好看但与节点含义无关”的误导。
- 已点亮节点始终保持清晰、明亮且可辨认；未点亮节点隐藏名称和内容，以问号和点亮价格表达。当前节点使用最强紫青动态辉光和尺寸提升，直接输入使用中强青色轮廓，可继续合成的输出使用较轻金色轮廓；三种关系同时用“当前 / 来路 / 去向”文字标签和连接方向表达，不能只靠亮度区别。
- 点击节点后不打开割裂上下文的详情模态框，也不把中央区域替换为单节点详情页。未选中节点时完全不绘制关系线；选中后只突出当前节点的直接输入和直接输出，也就是上下各一层的一跳关系，不继续展开整条祖先或后代链；点击图谱空白处取消当前选择。详细说明使用悬浮在图谱底部的非模态信息卡：左侧直接展示节点原始内容图，不重复套符文外框；图集内容必须使用与容器横纵比无关的固定窗口精确裁切，不能露出相邻格位。已点亮节点的内容图提供“查看大图”入口，点击后可以在屏幕中央临时放大同一高清源图；大图层只用于美术细节查看，点击层内任意位置或按 `Escape` 立即关闭并把焦点还给原入口。主体合成公式把“组成节点”和“动作 / 条件 / 环境 / 待学习知识”拆成上下两个独立分组，再共同指向当前节点，简短介绍保持次要。缺失项使用灰态与小锁同时表达，已具备的非知识资源只显示绿色小对号，不重复“已备”文字；已经永久学会的知识不再出现在公式和右侧当前需求框中，只有尚未掌握的知识继续作为准备项展示。已点亮节点不再重复显示“已永久点亮”。配方资源同时出现在右侧的小型需求框中。
- 每个尺度层必须可以在原图中完整展开，并提供“全部加载 / 加载未合成 / 加载已合成”三种手动策略。完整展开不是跳转到另一张分页表：该层在原图中向下撑开，按真实聚类拆成二级小组，每组 1—30 个节点、每行最多 6 个，可继续换行；骨架层同样每行最多 6 个。桌面图谱画布随中央可用视口铺满，不设置露出明显边界的固定最大宽度；节点仍以层级导航右侧区域为中心，常用缩放下不要求孩子横向拖动才能看全一行。画布边缘必须允许选中节点的双倍放大和辉光完整溢出，定位时为它预留可滚动空间，不能被内部表面裁切。层级卡必须明确提示“点击展开”，并显示当前已加载数量与总量。
- 右侧背包按“粒子包 / 动作 / 条件 / 环境 / 知识星图”分组，使用紧凑但触控面积不小于 48px 的方形格子。默认只显示图标和数量或永久点亮标记；hover、focus 或点击后显示名称、用途和购买状态。知识点是一次购买永久点亮，动作和粒子包使用可消耗数量；条件与环境是状态资源，不能伪装为背包消耗品。电子、质子既是图中的永久节点，也各自拥有独立的可消耗粒子包；每包 10 知识币，每次合成元素固定消耗电子包和质子包各 1 个。
- 当前配方最多突出展示 4 项关键准备。缺失的直接来路节点优先于资源显示，并提供跳转到对应节点的入口，不能出现“资源全部就绪但关键来路被隐藏”的误导状态；剩余位置再按缺失优先展示粒子包、动作、条件、环境和知识。缺少且允许购买的资源在原位提供紧凑的“补充”操作和知识币价格；补充按钮可以叠放在卡片次要信息区，但不得参与横向分栏并挤掉资源完整名称。不可购买的条件或环境明确写出“需要找到这个条件/环境”。点亮节点和购买资源都必须等待服务端文件保存成功后才更新页面，失败时保留原状态并给出可重试说明。
- 全量预览与进度调试使用顶部的紧凑快捷按钮：“点亮全部”“清空全部”。两项操作必须通过服务端原子写入进度文件，按钮在保存期间进入禁用状态；“清空全部”采用限时二次点击确认，第一次点击只改变按钮文案并给出说明，不能立即清除。无密码赠币按钮不得出现在儿童操作区。批量操作完成后重新读取当前骨架、已展开尺度层和选中节点，避免加载策略与实际进度不一致。
- 知识币余额与节点价格来自服务端内容目录和个人进度文件，初始余额为 0。基础加减、复杂运算和猫鼠游戏分别按每题 1、5、20 币即时奖励；奖励状态与总余额使用文字和数字共同反馈。同一答题事件必须幂等，奖励失败不能阻断答题。任何知识币、点亮、永久知识和动作数量不得使用 localStorage、sessionStorage 或仅内存作为事实来源。
- 知识币重置属于家长功能页：明确展示当前余额、密码输入、重置范围和结果状态。重置按钮至少 48px，提交期间禁用；密码错误时说明余额未改变，成功时说明余额归零但塔内发现和背包不受影响。页面不能自动重置，也不能把固定密码显示在儿童界面。
- 2000 个以上节点不得一次渲染。首屏请求覆盖全部层级、约 100–160 个节点的“全塔骨架图”轻量切片，节点必须来自真实配方并携带关系数据，但常态不渲染连线；选择节点后再显示上下各一层的一跳关系。更大的同层分支以后通过视口邻域或按需展开加入原图，不得退化为主界面的分页 Tab。独立图片优先使用 WebP，外框保留透明 PNG；大批量节点允许按固定行列使用高清 PNG/SVG 图集和 CSS 精确格位裁切，浏览器只随当前可见节点加载涉及的图集，禁止为 2000 个节点制造 2000 个首屏请求。
- 节点状态至少覆盖锁定、已点亮、当前、来路相关、去向相关、加载、空图占位、不可购买和保存失败。所有节点必须可键盘选择，工具提示可以通过 focus 触发，关系方向有可读文字，动态辉光在 `prefers-reduced-motion` 下替换为静态边框与尺寸差异。

- 图谱节点的中文名称不得小于 24px；当前节点在原图中放大到普通节点约 2 倍，并保持最高层级，便于孩子看清内容图片。放大不能改变其他节点的坐标或造成整层跳动，也不能把放大后的透明矩形变成拦截点击的热区；已选中节点应允许指针穿透到被它视觉覆盖的相邻节点，键盘焦点仍保持可用。必要时通过视口定位为它预留可见空间。

## 5. 动效与声音

- 微交互：按钮 140–180ms；选项边框/光晕 140–180ms；面板/提示进入 180–260ms。
- 环境动效：吉祥物或轨道可 3–4 秒轻微浮动；星点可以极慢闪烁。不能同时让多个大元素持续运动。
- 成功动效：星屑/彩纸不超过约 2 秒，每次只在明确完成、升级或首次达成时触发。
- 所有动效遵循 `prefers-reduced-motion`；减弱模式下保留状态变化，移除位移、旋转、闪烁和粒子。
- 声音默认关闭或遵从用户显式选择；不能自动播放。声音开关需要可见且可通过键盘操作。

## 6. 儿童与无障碍规则

- 关键内容使用足够的文字和背景对比；浅色青、粉等只能用于装饰或大面积色块上的深色/白色文字，不能直接承载细小正文。
- 焦点状态必须明显可见；所有可点元素均可键盘操作。
- 主要操作按钮应配合图标 + 文字，例如“▶ 开始任务”，不要只放图标。
- 题目一次只给一个明确目标；无法完成时给一个小提示和“再试一次”，而不是同时暴露所有答案。
- 不以倒计时、红色闪烁、连败提示制造压力。计时功能必须可暂停/关闭。
- 提供可读的状态播报（`aria-live`）给成功、保存、导入失败等反馈。

## 7. 新页面/新组件实施流程

1. 先从本文件的组件族中选取或组合模式，明确儿童端还是家长端。
2. 使用 token，而不是重新挑一套颜色、圆角或阴影。
3. 设计完整状态、移动端布局、键盘焦点、减弱动效和空/错/加载状态。
4. 新的通用 UI 模式先补充到本文件，再在正式设计系统组件目录中实现。
5. 完成后检查：首屏是否聚焦核心任务、文字是否足够大、装饰是否压过内容、动效是否有明确目的。
