# 分子工厂功能规范

状态：**已实现**

本文定义“化学 → 分子工厂”的统一物质资产、自由投放、自动/手动合成、原子团、本地恢复和可访问性语义。旧名称“化学聚宝盆”及旧地址只用于本地缓存和路由迁移，不再作为产品名称。

## 1. 功能定位

“分子工厂”是开放式原子组合玩法。孩子从前 90 号元素中自由投放原子，观察游离原子运动，并选择让工厂自动合成，或从反应区底部短暂出现的候选卡中亲自选择一种物质。

这里展示的是虚拟组成关系，不是现实化学反应模拟器：

- 不提供温度、压力、点火、比例、制备方法或实验步骤；
- 不暗示任意原子在现实环境中都能直接生成页面物质；
- 离子晶体、水合物和材料结构使用组成或代表片段示意；
- 页面只在本设备保存探索状态，不保存姓名、账号或学习成绩。

## 2. 统一化合物关键资产

所有化学功能只消费 `content/chemistry/compound-catalog.v1.json` 这一份运行时目录。它是分子工厂、反应熔炉和元素周期表之间的唯一化合物事实来源，当前包含 518 条记录。

目录由以下维护源生成：

- `molecular-structures.v1.json`：权威离散分子拓扑；
- `element-compounds.v1.json`：元素覆盖和特殊材料结构；
- `curriculum-compounds.v1.json`：教材常见物质、反应和材料；
- `pubchem-compound-properties.v1.json`：504 个 PubChem CID 的批量属性与图集索引。

每条目录记录必须包含稳定 ID、中文/英文名、原始与显示化学式、组成计数、类别、结构表示、来源、儿童可读摘要、组成说明、至少三个观察要点和安全说明。有 PubChem CID 的 502 条运行时记录还必须带分子量、IUPAC 名称、电荷、氢键、极性表面积等数据及本地图集坐标。

`apps/web/public/images/chemistry/pubchem-compounds.v1.png` 是 24 × 21 的本地二维结构图集。图片来自 PubChem PUG REST，目录保存 CID、来源页、替代文字和坐标；没有可靠 CID 的少数材料不得冒用图片，继续显示现有球棍或组成示意。

维护命令：

```bash
pnpm content:chemistry:catalog:refresh
pnpm content:chemistry:validate
```

前一条命令需要联网并重新抓取 PubChem 属性与图片；只修改本地维护源时可运行 `pnpm content:chemistry:catalog:generate` 离线重建统一目录。

## 3. 元素选择器与原子预算

- 右侧固定呈现原子序数 1—90，每行 9 个；元素格显示序数、符号、中文名、已收集物质数和游离原子数。
- 点击、触控或键盘激活元素格时，同时选中元素并投放固定批量：氢和碳 5 个、氧 3 个、其他元素 1 个。
- 反应区最多保留 240 个游离原子；剩余容量不足时整批拒绝，不能只投入半批。
- 元素颜色、结构语义和原子运动继续与反应熔炉一致。

## 4. 两个合成选项

顶部提供两个独立勾选框，均有勾选图形、文字、边框变化、键盘焦点、禁用和移动端状态：

### 不创造有机物

- 默认不勾选。
- 勾选后，自动匹配与手动候选都排除 `family = organic` 的全部记录。
- 已经收藏的有机物不被删除；正在聚合的物质完成后才应用新筛选。
- 同一批原子仍允许匹配氢气、碳单质等无机物，这不属于有机物创建。

### 自动合成

- 默认勾选，行为兼容旧版：连续投放停顿约 520 毫秒后，工厂自动选择最佳可组成物质。
- 未勾选时绝不自动消耗原子。工厂随机选择最多 3 个当前可组成且未收藏的物质，在原子运动区底部显示可点击提示卡。
- 每张卡使用较宽、较矮的横向形态，只显示化学式和中文名；整张卡均可点击，不再重复显示“点击合成”。卡片约 5 秒内缓慢漂浮并淡入淡出，忽略后自动消失，不改变原子池。
- 点击卡片时再次校验当前原子、完成状态和有机物筛选；校验通过才扣除原子并启动原有聚合动画。
- 新投放、切换筛选或完成一次聚合后重新计算候选；提示区最多同时存在 3 张卡。每批自然消失后自动展示下一批，在候选足够时优先避开上一批，直到没有可合成物质、重新开启自动合成或开始聚合。

## 5. 配方优先级与唯一性

候选物质只保留前 90 号元素可组成、总原子数至少为 2 的记录。对完全相同的原子计数组成只保留一个代表，优先级为教材常见、无机物、稳定 ID。

自动模式按以下顺序选取：

1. 优先选择能够消耗当前已形成原子团的物质；
2. 在都使用原子团时，优先使用原子团所含原子更多、所需散装原子更少的物质；
3. 没有原子团参与时，优先恰好用完全部游离原子的物质；
4. 再按原子总数、元素种类、教材优先级和稳定 ID 排序。

同一物质本次探索只收藏一次；从成品架移除后才允许再次合成。单原子单质不收藏，多原子单质允许收藏。

## 6. 游离原子团

工厂维护 10 种常见原子团：氢氧根、硝酸根、硫酸根、碳酸根、铵根、磷酸根、碳酸氢根、高锰酸根、亚硫酸根和亚硝酸根。

- 当游离原子满足某类原子团组成且当前没有同类原子团时，页面先把对应散装原子加入串行构建队列；原子逐渐靠近、连接并稳定成一个可持续漂浮的复合粒子。每类同时最多显示 1 个，不再使用右上角独立轨道框。
- 复合粒子必须显示标准原子团式和显式电荷数，例如 `SO₄²⁻ / 电荷 −2`；反应区左上角的组成清单同时显示 `SO₄²⁻ ×1 / 硫酸根 / 电荷 −2`。
- 原子团是真实的中间库存：形成稳定时从游离原子池扣除对应原子；匹配化合物时，它所包含的原子全部计入可用配方。
- 若目标化合物只需要一份该原子团，直接消耗完整原子团并让它保持整体形态靠近构建中心；若目标需要两份或更多同类原子团，界面上的一份作为完整原子团使用，其余份数由散装原子补足。
- 原子团参与化合物后从漂浮区和组成清单移除；后续重新投入足够原子时可以再次形成，同类原子团在任一时刻仍只有一个。
- 当多个原子团与化合物同时满足条件时，统一构建队列一次只执行一项：先完成当前原子团或化合物，再计算并启动下一项，禁止一帧内批量生成多个结果。
- “清空原子和原子团”同时清空游离原子与当前原子团，但保留成品收藏；“重新开始”清空游离原子、原子团和成品。

## 7. 页面、动效与可访问性

- 桌面端仍为左侧大反应区、右侧元素表，成品收藏架紧贴反应区下方；窄屏改为自然纵向排列。
- 普通原子和游离原子团共享反应区边界，分子工厂中的运动速度统一为反应熔炉默认速度的 50%；手动合成提示位于底部且采用宽而矮的卡片，尽量减少对运动区的遮挡。
- 原子团构建使用独立的紫青能量环、少量星点、逐步靠近与稳定闪光；化合物构建显示当前排队项，并让完整原子团与散装原子共同合并。单次闪光克制且不覆盖全屏，减弱动效下改为静态光环和短淡入。
- 金刚石仍保留事实源中的 10 原子代表性晶格片段；儿童界面的结构预览采用 `1 / 2 / 3 / 4` 四行三角锥式展示，并在行内和相邻行之间连接小三角形，避免原先支散难辨的视觉效果。该布局仅用于帮助观察，不替代真实四面体晶格说明。
- 提示卡、选项、元素格和移除操作均可用键盘完成，触控目标不小于 48px，状态变化使用可见文案和 `aria-live`。
- `prefers-reduced-motion` 下停止漂浮、震动和持续环境动画；手动提示卡保持静态可见，仍在约 5 秒后按逻辑消失。
- 页面持续显示“虚拟组成演示，不是实验步骤”。

## 8. 本地缓存与迁移

新缓存键为 `mumu.chemistry.molecule-factory`，稳定玩法 ID 为 `chemistry-molecule-factory`。内容包括游离原子、收藏 ID、选中元素、被中断的聚合 ID、两个勾选项和已形成原子团 ID。

- 继续兼容 `mumu.chemistry.treasure-basin` 与 `mumu.chemistry.treasure-box`；读取成功后按新结构写入。
- 缺少新字段的旧记录默认“不排除有机物 + 自动合成 + 尚未形成原子团”。
- 恢复时验证 240 原子上限、前 90 号元素、目录 ID、原子团 ID、布尔设置和唯一性。
- 若页面在聚合中关闭，恢复时把该物质原子归还游离池，再按当前模式重新计算。

## 9. 测试基线

自动化测试至少覆盖：

- 统一目录恰好 518 条、稳定 ID 唯一、81 种元素覆盖、502 条运行时图片坐标正确；
- 分子工厂候选不含单原子记录且每种原子计数组合唯一；
- “不创造有机物”同时作用于自动匹配与手动候选；
- 手动候选最多 3 个、ID 不重复且点击前确实可由当前原子组成；
- 每类原子团同时只存在一个，正负电荷与标准式正确，形成时消耗对应原子；Canvas 与左上角清单均呈现已形成原子团；
- `Na + HCO₃⁻` 可直接组成 `NaHCO₃`；需要两个同类原子团的物质使用一个完整原子团和一份散装原子计量；
- 清空操作同时移除游离原子和原子团，成品收藏保持不变；原子团和化合物通过同一串行队列逐个构建；
- 金刚石展示布局稳定为 `1 / 2 / 3 / 4` 四行、10 个碳原子和三角形连接；事实源结构保持不变；
- 分子工厂游离粒子采用 50% 速度倍率，手动候选消失后自动轮换并优先避开上一批；
- 氧气/臭氧、水优先级、完成唯一性、移除后重建和 240 原子上限；
- 本地缓存有效恢复、旧版本迁移、损坏拒绝和写入失败降级。
