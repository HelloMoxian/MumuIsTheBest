# 星页数独

正式入口为游戏大厅的“星页数独”，地址 `/games/sudoku`。页面使用 React + TypeScript，Fastify 负责题目、进度和通关校验。运行时不依赖 `temp/` 原型。

## 六档与双币奖励

| 难度 | 阵列 | 每宫 | 已知格 | 知识币 | 能量币 |
|---|---|---|---|---|---|
| 1 星芽启程 | 4×4 | 2×2 | 10 | 30 | 30 |
| 2 月光寻路 | 4×4 | 2×2 | 7 | 50 | 50 |
| 3 彗星探险 | 6×6 | 2×3 | 23 | 70 | 70 |
| 4 星云解谜 | 6×6 | 2×3 | 16 | 90 | 90 |
| 5 银河领航 | 9×9 | 3×3 | 42 | 110 | 110 |
| 6 宇宙织梦 | 9×9 | 3×3 | 30 | 130 | 130 |

每种币每局奖励 = 30 + 20 ×（难度序号 − 1）。重复挑战同一档的新一局仍按该档金额奖励；难度与关卡是同一个六档序号，不按累计通关次数额外增加。根据本次用户要求固定发放，不加入数学玩法的随机三倍活动，不设倒计时或速度门槛。

## 核心玩法

- 五套本机美术：宝石、元素徽章、数字、英文字母和宇航员。候选列表、提示、格内摘要使用同一图案；没有辅助编号，数字主题本身仍是数字图像。
- 点格子展开候选；点图案打叉，再点恢复；收起后保留问号和小图案。4×4 / 6×6 最多显示四张、9×9 最多三张，多余候选用省略号表示。只剩一种自动填写，全排除时提示恢复。
- 可直接填写、重新考虑、清空、撤销最多 200 步。直接填写允许假设，不用隐藏答案提前阻挡；行列宫重复用叹号及边框提示。
- 题目固定格保留金色内框和圆点，选中、冲突和宫边线同时可见；自己填写的格子没有固定内框。
- 方向键导航，1—9 / A—I 按候选顺序操作，Escape 收起，Delete / Backspace 清空。数字处理限定在本棋盘及工作台，不另设全局数字提交协议。
- 全盘正确后锁定本局并提供下一档或再来一局。中途开始新局时，弹窗明确提醒替换未完成棋盘。

## 题目与故事

服务端使用随机回溯及合法结构置换生成终盘，随机或中心配对次序挖空，每次挖空都计算最多两个解，仅接受唯一解。给定数量必须精确符合难度；最多 40 次整盘尝试后仍不足则报告失败，不降级难度或使用固定关卡。

故事基于共享主角、地点、任务、障碍/行动/结果和礼物语境组合。每行切成 n 段并按该行终盘符号映射，实际填写顺序决定故事碎片排列，整行正确时完成这一段故事。4、6、9 行组织为短、中、长故事。故事片段可以作为儿童理解线索。客户端不接收终盘、随机种子或撤销历史。

已拼好的故事可主动朗读，复用 `apps/web/src/shared/speech/` 的分句、暂停、继续、停止；不自动朗读，不接入 ASR。声音不可用时保留所有视觉操作。每次填写/换局和离页停止旧朗读，遵从全局音频协作规则。

## API 与存档

- GET `/api/games/sudoku`：读取公开棋盘、最近 30 次通关、累计完成数和待补发奖励；空数据不自动开局。
- POST 同地址：只接受明确的 `new / note / cross / set / clear / undo / hint` 命令，必须带 UUID operationId 和 revision；已有棋盘操作还需 gameId。每种命令由严格 Zod schema 校验，不接受客户端奖励或通关声明。
- 写入命令序列化，同一 operationId 的相同命令可重试；ID 内容冲突、旧修订号或旧局 ID 返回 409。固定格及超出本档范围的填写返回 422。提示只按当前行列宫推导，不改变候选或游戏修订号。
- 首个正式存档 schemaVersion 1，稳定 ID 为 `game-sudoku`，路径 `APP_DATA_DIR/learning/games/sudoku-state.json`。含创建/更新时间、当前题目、候选和撤销、通关记录、最近 200 条操作回执。
- 每次读写校验棋盘规模、给定数、唯一解、候选、故事结构和通关一致性。损坏文件、未知版本或旧临时原型格式拒绝加载并保留；不自动导入试玩棋盘、历史或余额。
- 写入使用单队列、同目录临时文件与原子替换，目录 0700、文件 0600。写入失败不先发币；浏览器保留同一操作供重试，不在 localStorage/sessionStorage 另存儿童进度。

## 发奖与恢复

通关资格和固定奖励先原子保存为 pending，再分别调用知识币和能量币钱包。钱包使用 `sudokuRewards[gameId] = 难度序号` 作为持久回执，金额由服务端再次按难度计算，ID 与难度不一致会拒绝。两边完成后才保存 granted。

一方钱包或最后的到账标记写入失败时，通关保持 pending。服务启动、读取数独及后续操作均尝试补发；已入账一方不会重复发放。两种币分属现有两个文件，属于可恢复的最终一致性，不宣称跨文件原子事务。页面可显示“通关已保存，奖励待补发”并主动重试。

知识币继续写 `learning/world-tower/progress.json`，能量币继续写 `learning/games/fruit-slice-history.json`。新增默认空的数独回执字段兼容旧钱包，保留既有 schemaVersion、余额、其他玩法回执与交易。数独回执不随有限交易列表截断；调整余额时仍保留回执。

未来备份/恢复需将数独存档与两套钱包一起纳入同一恢复点，避免单独回退其中一个文件。没有增加新的钱包或浏览器存储协议。

## 验证

`pnpm --filter @mumu/server exec tsx --test src/sudoku.test.ts` 覆盖六档随机题唯一解、故事、候选、固定格、API 并发和重放、全局双币阶梯、重复关卡、写入失败、半途发奖和重启补发、旧钱包兼容、非法与未来版本保护。全部测试使用系统临时目录。

正式美术在 `apps/web/public/images/sudoku/`，原始生成图集和提示词在 `assets/game/sudoku/source/`，无在线图像生成依赖。
